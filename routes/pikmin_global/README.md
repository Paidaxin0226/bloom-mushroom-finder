# Pikmin Bloom 全球城市搜尋路線

`pikmin_all_25012_cities.json` 是可直接匯入 Bloom Mushroom Finder「座標序列」的完整合併路線。`popular/*.json` 與 `less_known/*.json` 則保留為兩個分類版本；`index.json` 是完整索引，不是搜尋序列。

## 內容

- 完整合併：25,012 座城市、15,255,195 個有效搜尋點、約 18.1 MB，共 1 份。
- 熱門城市：GeoNames 人口排序前 500 座，共 1 份。Berlin 在此分類。
- 冷門城市：其餘 24,512 座，共 1 份。Karimnagar 在此分類。
- 程式上限為 50,000 座城市、1,000,000,000 個搜尋點及 32 MB JSON；格點會逐筆惰性產生，不會一次展開整座城市。
- 城市資料採 GeoNames `cities15000`：人口超過 15,000，或國家首都。
- 國家篩選採 Freedom House 2026 的 Free 或 Partly Free；另明確排除 BY、CN、HK、MO、RU。印度包含在內。

Pikmin Bloom 官方支援頁沒有提供固定國家清單，而是要求使用者到所在地區的 App Store 或 Google Play 檢查。因此這套路線以遊戲可正常取得的民主／部分民主地區為涵蓋基準，並套用上述排除規則。

## 比例尺與範圍

- USB 實測畫面寬度：627.9 公尺（1080 px，0.5814 公尺／px）。
- 每個城市只注入一次中心 GPS 座標；城市內的長方形搜尋靠滑動手機地圖完成。
- 每次滑動後會監看地圖變化；有明顯變化才拍照辨識，連續 1 秒沒有變化就前往下一格。
- JSON 的四向範圍單位固定為 km（`left_km`、`right_km`、`up_km`、`down_km`）。
- 城市範圍採歐盟 JRC `GHS-WUP-DEGURBA R2025A` 的 2025 聚落實際多邊形，依序涵蓋 UC、DUC、SDUC 與 RC；25,001 座成功配對。
- 注入座標使用 GHSL 人口加權聚落中心，確保每座已配對城市都從聚落內開始，不再從 GeoNames 邊境點或空白外接框角落開始。
- `scan_spans` 以 `[y, 起始 x, 結束 x]` 壓縮每列有效格；只有手機畫面與聚落多邊形相交時才拍照辨識。外接長方形原有 36,278,497 格，其中 21,023,302 格空白邊角已遮罩排除。
- 配對時，真正包含 GeoNames 座標的聚落絕對優先；不在任何聚落內時才綜合人口與距離選擇鄰近聚落，再移入該聚落中心。
- 11 座無法配對 GHSL 邊界的城市使用每平方公里 300 人的低密度人口面積估算，並以 `coverage_source` 明確標記。
- 參考手機為 MI 9、1080×2340；水平每格 0.413949 km，垂直每格 0.897664 km。
- 初始中心畫面已覆蓋水平 0.313950 km、垂直 0.680225 km。各方向格數仍使用 `ceil((邊界距離 km - 半個畫面 km) / 每格 km)` 強制進位，再由多邊形有效格帶排除外接矩形中的空白區。

完整統計、來源 URL、來源檔 SHA-256 與各分卷點數請見 `index.json`。

## 記憶體管理

- 編輯器每頁只建立 50 張節點卡片，不會一次渲染 25,012 張；手動修改座標或四向範圍時會清除已失效的形狀遮罩。
- 後端以 generator 逐格產生目前城市的搜尋點，不會把大型城市的完整格點放入記憶體。
- 命中內容逐筆附加到 `detections.jsonl`，記憶體只保留命中數量。
- 啟動工作時會丟棄原始大型 HTTP 請求，只保留已正規化的節點與少量執行設定。

完整合併檔實測解析與有效格帶正規化的 Python 追蹤峰值為 165.69 MiB；釋放原始 JSON 後約 66.50 MiB。詳細數據見 `memory_report.json`。
