## 優先修正

### F01 / P1：清空經緯度會變成有效的 0

**已在 UI 重現。** 序列管理 → 第一個 LAT 欄位 → Ctrl+A → Backspace。原本 25.033 直接變為 0，沒有必填警告。這不是只有匯入 JSON 的問題，而是序列編輯欄位本身。

影響：使用者準備重輸座標或漏填時，可能把赤道當成有效節點保存並執行。LNG 使用相同轉換，亦有相同風險。

位置：`frontend/src/components/GeoPanel.tsx:663`，`Number(event.target.value)` 把空字串轉成 0。後續 normalizer 看見數字 0，無法知道使用者其實清空欄位。

建議：輸入草稿保留字串，空值與無效值阻止保存／開始；在對應欄位顯示錯誤。驗收時同時測空白、單獨負號、貼上非法內容、合法的 0。

### F02 / P1：微調座標會無提示地失去建成區搜尋範圍

**已在 UI 重現。** 載入「Pikmin 冷門城鎮・建成區搜尋」，23,904 節點、1,112,642 搜尋格。第一站 Sangli 緯度 16.8557354 按一次向上，再按一次向下回到原值。搜尋格增加為 **1,112,706**，沒有恢復，介面只顯示未保存。

原因：`GeoPanel.tsx:370–373` 在座標或範圍的任何更新清掉 `scan_spans`。第一站原本有效格帶共 98 格，失去格帶後變成完整 18×9＝162 格，多出 64 格。改回數字仍然沒有原格帶。

影響：原本只搜尋建成區，會變成包含原本排除區域的完整矩形，增加時間且使用者不易察覺。座標改動可能確實需要重新計算覆蓋，但不能無聲改變搜尋策略。

建議：清楚提示「此修改將失去建成區篩選」，提供重新計算、保留原版本、撤銷修改；回到原值時能還原原格帶。測試草稿未保存，原路線檔未更動。

### F03 / P2：讀到精確座標後，重複需要重啟遊戲才能回到搜尋

**實機重複出現。** 第一輪每次在相同中心命中 Event_2026_09 後，都進入「搜尋位置局部校正未完成：畫面已離開 2D 地圖」→「重新準備遊戲與目前搜尋格」→ 重啟 Pikmin Bloom。

可對照紀錄：

- 01:08:48 開始擷取 → 01:08:55 地圖恢復失敗 → 01:08:58 重啟 → 約 01:09:27 才繼續。
- 01:10:12 開始擷取 → 01:10:19 相同失敗 → 01:10:21 重啟 → 約 01:10:50 恢復。
- 第三個節點再次出現相同恢復路徑。

精確座標有成功保存，不能稱為座標擷取失敗；異常在返回原搜尋畫面的穩定性，每次額外增加約半分鐘。最終 summary 的 `capture_failures=0` 與 memory watchdog 的 `restart_count=0` 都沒有反映這類恢復成本。

定位入口：`bloompilot/mushroom_coordinate.py:_return_to_map`、`_restore_view`。現有證據可確認退回／核對失敗，尚不能確定是哪一次 Back、返回按鈕或過場分類造成。建議保存每次退出詳情前後的診斷影格，針對這個案例補回歸測試；成功、恢復次數、恢復耗時應分開統計。

### F04 / P2：暫停在最需要等待的階段會取消要求

**UI 與 API 都有實測。** 第一輪 UI 在擷取／恢復期間按暫停，先顯示正在安全暫停，之後返回可按的暫停按鈕，工作继续；一般搜尋時再次暫停成功，耗時約 2.69 秒。

第二輪在工作開始後立即呼叫 pause，**15.05 秒後回覆「等待辨識工作進入安全暫停點逾時，請稍後再試。」**，工作繼續進入遊戲和節點等待。

原因：`bloompilot/web/runtime.py:381` 的 pause gate 在 15 秒期限到達時將 `_requested` 清為 false。遊戲準備或目標恢復很容易超過這個時間。

建議：以待暫停狀態保留要求，於下一個安全點生效；介面說明目前等待哪個步驟，讓使用者可以取消暫停要求或停止工作，而不必反覆猜何時重按。

## 使用體驗改善

### U01：重要控制鈕與预覽無法同時看完整

在預設約 1440×900 視窗，篩選與設定把管理序列、開始、暫停、停止推到第一屏外。往下捲到控制鈕，右側手機預覽上半部也被捲走。建議讓主要控制鈕固定可見，設定欄和預覽區分開捲動。

### U02：數字與模型名稱不便判讀

新節點範圍顯示例如 `1.5557966666666665`、`4.270882777777778` km。建議顯示合理精度，內部保留計算精度。模型清單中的兩個不同模型都叫「2026-09｜含活動菇」，只能用預設星號分辨目前選項，無法判斷訓練版本；建議補訓練名稱／時間或簡短版本。

### U03：序列預設隨機執行藏在進階設定

`randomizeWaypoints` 預設 true，但頁面切換名稱是「依序前往座標」，管理器又提供上下排序。建議在摘要明示「隨機／依序」，以及這次的實際執行順序，避免使用者整理順序後發現沒有按列表跑。這項為介面與程式檢查，第一輪測試固定關閉隨機以提高可重現性。

### U04：大型路線缺乏找城市與快速定位功能

23,904 點分成 479 頁，已成功載入，沒有因此崩潰。但只有頁碼與上一／下一頁，找指定城市不直覺，建議加城市／國家搜尋、跳到執行節點，以及選定子集執行。未測完整 23,904 點的長時間執行。

### U05：終止後訊息還停在「正在儲存」

第一輪 state=completed、第二輪 state=cancelled，兩者最後 message 都仍是「正在儲存辨識結果與序列摘要…」。建議完成時換為清楚結果：已掃描、跳過、命中、恢復次數、回原位是否成功，以及輸出入口。第一輪 completed=27/27 包含跳過的 9 格，應把實際掃描 18 與跳過 9 分開呈現。
