# 今日回顧、水面誤報與蘑菇座標修復

## 原因與修改

- **今日回顧誤判為地圖**：回顧步數頁及完成頁右下角的分享圖示會通過原本的定位圖示判斷。移除單靠定位圖示判定 2D 地圖的分支，必須確認返回與 2D／3D 切換控制。新增步數、心情、完成三個回顧畫面的辨識，優先於地圖辨識。依使用者選擇，自動選擇中間「普通」心情。
- **頁面中斷後繼續滑動**：掃描與座標恢復在手勢前檢查地圖；擷取到非地圖畫面時，丟棄該影格並恢復原搜尋格。恢復次數及時間均有上限，無法確認地圖時停止，不執行收尾定位手勢。
- **Large_Crystal 水面誤報**：2026-09-12 序列紀錄的五個水晶命中實際上是水池。新增僅針對水晶候選的水面／草地色彩檢查，保留水晶的低飽和切面與暖色菇柄。篩選套用於首次辨識、重新確認、即時辨識，位於座標擷取及通知之前。這是推論後篩選，沒有修改或重新訓練模型權重。
- **真正蘑菇無法重新對上**：觸發辨識的影格可能仍在滑動慣性中。座標擷取現在先等待地圖穩定，再比對地圖位移及目標身分；返回時恢復穩定後的畫面，而不是中途影格。點擊前再確認一次。即時辨識也改用同一套外觀及位移快取，取代固定像素格快取。

## 驗證

- 既有五張水池誤報裁切全部排除；真實水晶素材在陸地／水面、三種尺寸及兩種亮度下全部保留。
- 實機擷取回顧三個階段，確認步數「確定」、中間「普通」、「完成」後可恢復主畫面、3D、2D、最大範圍及北向。
- 實機成功取得一個模型辨識蘑菇的 `pikmin_map_intent` 精確座標，取得前後手機定位相同，並恢復搜尋畫面。
- 回歸涵蓋非地圖影格不辨識、恢復失敗不繼續操作、兩軸搜尋格重建、慣性滑動後目標核對、OCR 失敗不沿用舊按鈕及現有手機／序列／後端流程。

實機紀錄保留於 `scratch/daily_review_inspection/recovery_result.json` 與 `scratch/current_coordinate_validation/result.json`。測試用的去情境水池裁切及回顧畫面位於 `tests/fixtures/recognition_regressions/`。

回顧按鈕優先使用實機文字範本；其他文字按鈕使用本機 Windows OCR 作為後備。沒有辨識出可操作按鈕時會等待並在逾時後停止，不猜測座標。水面篩選仍需在未來模型或遊戲美術改動後以新樣本驗證。

後續已加入負樣本微調模型；本文件的「沒有重新訓練」描述的是第一階段修正。訓練方法與不經顏色篩選的比較見 [2026-09-13 訓練紀錄](CRYSTAL_TRAINING_2026-09-13.md)。
