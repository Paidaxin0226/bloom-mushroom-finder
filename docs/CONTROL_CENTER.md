# BloomPilot Control Center

BloomPilot 的 Windows 控制中心統一使用 Electron + React/TypeScript；Python FastAPI 後端只負責裝置、工作與資料 API，不依賴 Tkinter。

## 啟動

```powershell
# 第一次安裝或修復
.\01_安裝環境.bat

# Electron UI
.\啟動BloomPilot控制中心.bat

# 快速驗證環境
.\啟動BloomPilot控制中心.bat --check

```

啟動時 Electron 會建立本機動態 API 埠並管理 Python 子程序；不需要另外開一個 terminal。關閉視窗時會先安全停止工作與裝置 session。

## UI 組成

- `Sidebar`：USB 裝置、六個功能入口與版本狀態；辨識功能集中在單一入口。
- `DeviceStatus`：掃描 ADB、選擇手機、輸入 PIN、配對／中斷。
- `MapView`：Leaflet 地圖、裝置位置、目的地與點選座標。
- `ControlPanel`：瞬移、導航、速度、道路選項、暫停／停止／還原與步數注入。
- `WorkflowPanels`：背景蒐集、資料集、訓練及自動搜尋辨識；各功能的持久設定在對應頁面管理。
- `GeoPanel`：以一般工作頁編輯並執行座標序列；每個節點可分別設定等待時間、命中座標換算距離與左、右、上、下四向滑動格數，地圖只在選點彈窗中載入。
- `StatusBar`：後端、Android、GPS、目前工作與時間。
- `useWebSocket`、`useDevice`、`useJobs`：把即時狀態與頁面元件分離。
- `services/api.ts`：集中管理所有 REST endpoint 與錯誤處理。

## Android USB 配對

1. 安裝 `android/` 產出的簽名 release APK。
2. 手機以 USB 連接電腦並允許 USB 偵錯。
3. 開啟 Android App；「電腦 USB 控制」會自動啟動，不需要再到「連線」頁手動開啟。
4. Android 系統授權這台電腦進行 USB 偵錯後，BloomPilot 啟動時會優先自動連接上次成功使用的手機；若沒有紀錄且只有一台可用手機，也會直接連接並透過 ADB 自動啟動手機端 USB 控制通道。只有同時出現多台且尚未選過時才需要在左側手動選擇。

通道使用 ADB dynamic forward 連到 Android local-abstract socket，不開放 LAN port。座標序列執行期間每 15 秒傳送一次輕量狀態心跳；若 Windows、ADB 或手機暫時重設通道，會自動重建 forward、重新配對並重送目前控制指令一次。新版 Android 服務也不再因辨識期間只有截圖／滑動、控制通道閒置 45 秒而主動斷線。

辨識中的 scrcpy 若超過 3 秒沒有新影格或串流中斷，會改用 ADB 取得當下畫面並繼續目前搜尋；串流恢復新影格後自動切回。備援不會重用舊畫面，若 ADB 截圖也失敗，仍依原本的取樣失敗處理停止或略過。

## 功能頁

- 「裝置控制」：在地圖選點，操作定位與步數。
- 「手機辨識」：以頁內模式列切換「自動搜尋辨識」與「座標序列辨識」，模型選擇器可將現有 trained model 保存為兩種模式共用的預設模型。目標種類與人數篩選也可保存為兩種模式共用的預設；「全部目標」會同步勾選或取消所有個別目標。
- 辨識開始與記憶體重啟都使用同一個地圖準備狀態機：重啟遊戲、連續畫面確認可選安全警示、在主畫面按中間底部指南針進入 3D、再按右側 3D／2D 切換進入 2D、雙指縮到最大範圍、有定位按鈕時回到自身位置，最後按右上指南針讓北方向上。3D 畫面即使無法分類，也會依已確認的主畫面階段繼續第二次切換。
- 「自動搜尋辨識」：左、右、上、下可設為不同格數，介面會即時計算搜尋矩形尺寸與總格數；也可用「互動建立範圍」依序逐格滑動並查看手機預覽，每一方向確認後會自動回正，完成四方向後直接套用格數。正式辨識不使用固定格點等待：畫面出現明顯變化後拍照辨識，連續 1 秒沒有變化便前往下一格。「命中座標推估」可在右下角定位按鈕出現且自身位置仍在畫面內時量測此手機比例尺；系統以短距離緯度位移追蹤自身位置的上下往返像素量，再利用北向 2D 地圖的等比例特性推算水平比例尺，避免水平探測把自身位置移出畫面。辨識依手機序號載入校正值，再用 USB 目前座標、掃描格與辨識框中心換算約略經緯度。「即時命中」卡可選擇啟用 Discord Webhook；先貼入 Discord 官方 HTTPS Webhook、傳送測試播報，再儲存設定。Webhook 背景發送失敗不會中斷辨識。
- 辨識按下「暫停」並進入安全點後，桌面端會自動開啟 scrcpy 鏡像控制視窗。可用滑鼠點擊、拖曳及鍵盤直接完成原本需在手機上進行的操作；「重新開啟手機控制」可重建被關閉的視窗。按「繼續辨識」或「停止」時會自動關閉鏡像，繼續流程會依舊回復搜尋座標與遊戲狀態。
- 「座標序列辨識」：主表單只顯示目前序列摘要；所有內建與自訂序列共用一個 `routes` 清單。節點編輯、地圖新增、保存、刪除及 JSON 匯入／匯出集中在「管理序列」視窗。瞬移／導航及完成後行為收在「進階執行設定」。執行中可按「跳過目前節點」，中止目前節點的等待、導航或剩餘搜尋，直接前往下一點；已取得的結果會保留，跳過的節點及剩餘格數會寫入工作摘要。另可按「刪除目前節點並前往下一節點」，直接從執行工作綁定的原始 route 永久移除該節點（包含內建 route），保存成功後才前往下一點。此操作保留其餘節點、排列及已有結果，隨機執行時仍以節點 ID 定位；寫檔失敗則不跳過。未保存的序列會在啟動前自動保存至 `routes/imported`。跳過或刪除最後一個執行節點會正常結束序列並套用完成後行為；刪光節點後保留空 route，可重新載入並新增節點。暫停時須先繼續辨識才能跳過或刪除。
- 「背景蒐集」：以畫面中心逐圈拖曳，保存到 `data/source/backgrounds/<城市>/`；等待時間與範圍可在本頁保存為預設。
- 「資料集產生」：由背景與透明 target 產生固定方框 YOLO detection 資料集；合成數與平行工作數可在本頁保存為預設。
- 「模型訓練」：在本頁設定 epochs、image size 與 batch 上限後啟動 training worker，可保存後暫停或安全停止。

各功能頁保存的預設值仍以深層覆寫方式寫入 `runtime/phone_automation/settings.json`，不會改寫 `config.yaml` 或破壞其中註解。

同一時間只允許一個重工作；因此訓練、座標序列、背景蒐集與自動搜尋辨識不會爭用 GPU、ADB 或 Android movement。

### 座標序列執行順序

1. Electron 將完整序列交給 `geo_sequence_recognition` 工作。
2. Python 只載入一次 YOLO 模型。
3. 透過 Android USB command channel 前往第一個經緯度。
4. 等待該節點的 `wait_seconds`，預設 10 秒。
5. 先辨識中心，再透過 ADB 滑動手機地圖，依該節點的左、右、上、下格數搜尋長方形範圍；格點之間不再注入 GPS 座標。每格會監看地圖畫面，偵測到明顯變化後拍照辨識，連續 1 秒沒有變化便前往下一格。
6. 每個城市掃描完成後回正手機地圖，再前往下一個城市；辨識命中只會保存紀錄，不會中止搜尋。`spacing_m` 只用於換算命中的約略座標。
7. 若啟用「序列結束後回到最初座標」，最後會回到執行前的位置。

結束或安全停止時，回原點／停止定位移動的 USB 收尾階段最多等候 8 秒，包含停止心跳與等待控制通道。心跳每次最多等候 3 秒；收尾不會再啟動長時間重連。若手機未確認指令，會顯示「無法確認已回到最初座標」或停止移動失敗的訊息，並繼續保存已取得的辨識結果；`summary.json` 的 `final_movement` 會記錄這次收尾是否成功。

自訂與匯入序列統一保存於專案 `routes/imported/*.json`，並和其他 `routes/**/*.json` 顯示在同一個清單。內建序列不可直接刪除；修改後保存會建立自訂副本。舊版 `settings.json` 的 `geo_sequences` 會在首次開啟序列頁時自動遷移並移除舊欄位。

大型座標序列最多支援 50,000 個節點、500,000 個搜尋點與 32 MB JSON。節點編輯器每頁只渲染 50 筆；辨識後端逐城市建立格點，命中紀錄直接寫入 JSONL，避免長路線持續增加記憶體占用。

## 輸出

背景檔名會從城市資料夾現有最大編號接續。自動搜尋與座標序列辨識各自建立 `outputs/recognition/<工作_時間>/`，保存原圖、標框預覽、JSONL detections 與 summary。每月訓練的中間資料、舊月份背景與過期模型由程式自動清理。

## 開發模式

```powershell
# terminal 1
.\.venv\Scripts\python.exe -m bloompilot.web.server --port 8765

# terminal 2（只在瀏覽器檢查 renderer）
cd frontend
npm run dev

# 或由 Electron + Vite HMR 一次啟動
npm run start:dev
```

一般使用不需要上述兩個 terminal；直接執行 BAT 即可。
